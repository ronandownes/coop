## Explain clearly

Start with the audience: what do they already know, what do they need to decide, and what detail would only add cognitive load?

A strong explanation moves from **familiar → essential idea → example or visual → check understanding**.

## Technical to non-technical

The aim is not to remove the mathematics. It is to expose the decision hidden inside the mathematics.

For example, a lease-finance dashboard can let a stakeholder compare deposit, monthly payment, interest rate, term and residual value without forcing them to read the underlying equations first.

## Visual communication

Use a graph, dashboard, table or diagram when the shape of the information matters more than the individual numbers.

Good visualisation should reduce dimensional overload, make comparisons easier and let a decision-maker ask better questions.

## Language worth noticing

Erik does not need to sound ornate. He should start noticing why some language is easier to remember and easier to say.

Useful things to notice include:

- **alliteration** — repeated starting sounds
- **assonance** — repeated vowel sounds
- **rhythm** — sentence shape that makes a phrase easier to retrieve
- **analogy** — explaining an unfamiliar idea through a familiar one
- **contrast** — setting two ideas beside each other so the distinction becomes clear
- **precision** — choosing the word that says exactly what is meant

The point is not decoration. The point is **clarity, recall and confidence**.

## Learning through language

When a useful word appears in an answer, do not merely memorise the definition.

Try to be able to:

**define it → use it in context → contrast it with a nearby idea → give an example**

That turns vocabulary into usable interview language.
